> [!CAUTION]
> **ローカル学習専用・公開サーバへのデプロイ厳禁**
>
> 本プロジェクトは、ファイルアップロード設計の不備がどのようにサーバーサイドコード実行（RCE）へ至るかを安全に観察し、多層防御（Defense in Depth）を学ぶための**ローカル環境専用教育教材**です。インターネット公開環境、クラウドインスタンス、社内共有サーバー、カフェ等の信頼できない共有ネットワーク上での公開は絶対にやめてください。

## 1. 安全設計の基本方針（Safety by Design）

脆弱性を扱う学習環境では、「学習者がうっかり起動したままにした」「カフェの Wi-Fi に繋いだ状態で起動した」「サンプルコードが悪用可能な Web シェルになっていた」といった運用ミスが実害につながる恐れがあります。

そのため **Upload-to-Execution Lab** では、利用者の注意だけに依存せず、**コンテナ構成・ネットワーク・OS 権限・UI・サンプルペイロード・自動テスト**のすべての層に技術的な安全制約（ガードレール）を組み込んでいます。

---

## 2. 技術的ガードレール仕様

### 2.1 ホストループバック限定バインド（`127.0.0.1` 固定）

[`labs/01-php-upload-defense/compose.yaml`](../labs/01-php-upload-defense/compose.yaml) において、公開するすべてのポートは必ずホストのループバックアドレス `127.0.0.1` を明示してバインドしています。

- Stage 1: `"127.0.0.1:8081:8080"`
- Stage 2: `"127.0.0.1:8082:8080"`
- Stage 3: `"127.0.0.1:8083:8080"`

Docker Compose でホスト IP を省略した `"8081:8080"` 指定を行うと、デフォルトで全インターフェース（`0.0.0.0`）にバインドされ、同一 LAN 上の他端末からアクセス可能になってしまいます。本ラボでは `0.0.0.0` バインドを一切禁止しています。

### 2.2 コンテナネットワークの完全内部隔離（`internal: true`）

ラボ用ブリッジネットワーク `lab_net` には `internal: true` を設定しています。

- コンテナ内部から外部インターネットへのアウトバウンド通信（外部サーバーへのコールバック、パッケージや外部スクリプトの取得等）は Docker ネットワーク層で遮断されます。
- Web UI の HTML / CSS も外部 CDN・Web フォント・外部スクリプトを一切参照せず、ビルド完了後は完全オフラインで動作します。

### 2.3 非 root ユーザーでのプロセス実行

すべてのステージコンテナは、特権 `root` ユーザーではなく非特権ユーザー `www-data` で稼働します。

- Apache は特権ポート `80` ではなく非特権ポート `8080` で待ち受けます。
- 書き込み可能なディレクトリはアップロード先ディレクトリ（Stage 1/2 では `/var/www/html/uploads`、Stage 3 では `/var/lab-storage/uploads`）のみに限定されており、アプリケーションコード本体や Apache 設定ファイルは `www-data` から書き換えできません。

### 2.4 完全無害な固定マーカー検証ファイル（Web シェル化の排除）

コード実行の成立を確認するためのサンプルファイル（`samples/marker-basic.php`、`samples/marker-bypass.phtml`）は、攻撃用 Web シェルではなく**無害な固定マーカー出力スクリプト**として設計されています。

- **出力する情報のみ**:
  - ステージ識別用の固定文字列（`LAB_EXECUTION_MARKER_STAGE1` / `LAB_EXECUTION_MARKER_STAGE2`）
  - 読み取り専用のランタイム情報（`PHP_VERSION`、実行プロセスユーザー名、コンテナホスト名、UTC 現在時刻）
- **厳格に禁止している要素**:
  - 外部リクエスト入力の参照: `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `$_FILES`, `php://input`, `$_SERVER['QUERY_STRING']` 等
  - OS コマンド実行・動的コード評価: `system()`, `exec()`, `passthru()`, `shell_exec()`, `popen()`, `proc_open()`, `eval()`, `assert()`, バッククォート演算子等
- これらの禁止事項は自動検証スクリプト（`tests/verify.php`）によって静的スキャンされ、違反があればテストが失敗する仕組みになっています。

### 2.5 常時表示の安全警告バナーとワンクリック初期化

- 全ステージの全画面上部に、日本語（`ローカル学習専用・公開サーバへのデプロイ厳禁`）および英語（`FOR LOCAL EDUCATIONAL USE ONLY - DO NOT DEPLOY PUBLICLY`）の警告バナーを常時表示し、スクリーンショットや画面共有時にも教育用ローカル環境であることが一目で判別できるようにしています。
- 各ステージの UI にある **Reset ボタン**（`POST /reset.php`）により、演習中にアップロードしたファイルを即座に削除し、クリーンな初期状態へ戻すことができます（Stage 1・Stage 2 でも `basename()` によるファイル名正規化を行い、アップロード用ディレクトリ外へのパストラバーサル書き込み・削除を防止しています）。

## 3. 利用者・勉強会主催者向け運用ルール

1. **使用後は必ず停止する**: 学習やデモが終わったら、`docker compose down` を実行してコンテナを停止・破棄してください。
2. **ポート公開・トンネルツールの禁止**: `ngrok`、`cloudflared`、`ssh -R`、ルーターのポート開放、WSL2 ポートプロキシによる外部インターフェース公開を行わないでください。ワークショップでは参加者各自の PC 上でローカル起動するか、講師自身の PC 画面を画面共有してデモを行ってください。
3. **脆弱なコードを本番プロジェクトへ流用しない**: `stage1-vulnerable` および `stage2-app-only` のコードはアンチパターンの教材です。実装の参考にする場合は必ず `stage3-defense-in-depth` の設計思想を確認したうえで、対象システムの要件に合わせたセキュリティレビューを行ってください。
4. **倫理的・合法的な利用**: 本教材で学んだ手法を、許可を得ていない第三者のサーバーや Web サービスに対して試す行為は不正アクセス禁止法等の法令違反となります。検証は必ずローカルの本ラボ環境内のみで行ってください。

## 4. コントリビュータ向け安全規約（将来のラボ追加時）

今後 [`docs/roadmap.ja.md`](./roadmap.ja.md) に沿って新しいラボ（`labs/02-...` 等）や機能を追加する Pull Request では、以下のチェックリストをすべて満たすことが必須です。

- [ ] `compose.yaml` のすべての `ports` が `127.0.0.1:` プレフィックス付きで定義されていること（裸の `"8080:8080"` や `"0.0.0.0:..."` は不可）。
- [ ] コンテナネットワークに `internal: true` が設定され、外部インターネットへの到達性がないこと。
- [ ] アプリケーションコンテナが非 root ユーザーで動作し、書き込み可能領域が最小限に絞られていること。
- [ ] すべての検証用サンプルファイルが外部入力を受け取らず、OS コマンド実行・任意コード評価プリミティブを含まない固定マーカー方式であること。
- [ ] 外部 CDN（Google Fonts、外部 JS ライブラリ等）への依存がなく、ビルド後に完全オフラインで動作すること。
- [ ] Web UI の全ページに日英両対応のローカル専用警告バナーが表示されること。
- [ ] `tests/` 配下に、正常系・脆弱性再現・多層防御・安全制約（静的スキャン含む）を自動検証できるスクリプトが同梱されていること。
